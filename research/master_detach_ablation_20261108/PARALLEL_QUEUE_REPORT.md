# 训练与评价并发调度

本次只改变独立 ablation 目录的 Python 调度。C++ 二进制、网络、Loss、训练步数、ratio、模型起点和评价口径保持原样。

训练和评价各一个 worker，可运行不同组。每组训练和模型校验成功后才能评价；尚未验证的数据集与相机入口仍执行原6步 smoke 和5项评价。

每个 worker 写自己的 JSON。只有主控制器写 LOD_PIPELINE.json 和指标总表，避免并发覆盖。恢复时核对 PID、start_ticks、boot_id；继续接管活 worker，禁止重复启动。worker 退出但原生子进程仍存活时保留现场，不发射替代任务。

每小时监督继续，分别检查每个原生进程的日志和步数，避免一个任务的进展掩盖另一任务的停滞。原健康停止、OOM重试计数及上限保持不变。

发射新任务要求 GPU 空闲显存至少6144 MiB、系统可用内存至少8 GiB；磁盘不足5 GiB暂停。corridors-dolly 双目保留29 GiB cgroup和整机2 GiB余量保护，该组运行时不与另一 worker 重叠。

22项CPU测试通过，包含两个真实CPU子进程重叠执行与独立状态合并、重复启动保护、训练完成依赖、高内存互斥、恢复、健康停止及OOM重试。正式GPU重叠的端到端收益需继续实测，不按两倍加速承诺。

串行控制器自然结束后交接，没有中断原生训练。交接前 office0 RGB-D 在第16498步触发局部 Scale 长尾：最大287.8倍，超过100倍占1.06%。已记为第1次健康失败。新版调度恢复后，从原Full进行第2次尝试；下一份有效模型产生后，评价与后续训练重叠。

回退时等待两个worker结束，确认没有活进程后将 PARALLEL_CONFIG.json 的 enabled 设为 false，再由原 run_batch.py 串行接管；保留所有评价和重试历史。
