# office3蒸馏Compensator连续升载测试

## 模型与任务

Replica office3 RGB-D完整2000帧。使用该地图绑定的32/32学生、四个线性Head、3534参数，checkpoint为Replica__office3__rgbd/continuous_calibration/best.pt；SHA256为20bcf17294a4eeec7d493246742882d04767a74e7ddfd3dff50fd4349fb6ac90。

学生使用已验收的v31部署入口，v27不支持该结构。正常FP32、TF32关闭，保持原Selector和Anchor Feature，使用原Rasterizer。

帧i从0开始，t=i/1999，目标负载u=0.2+0.6t，请求预算B=floor(4000−3000t+0.5)。首帧20%/4000点，末帧80%/1000点。实际K=min(B,合格候选数E)，记录预算、K、名义Anchor可见候选数及radii>0点数。

五种方法：CaRtGS Full、我们未补偿Master Full、学生固定4000点、学生固定1000点、学生Adaptive。三轮轮换方法顺序，同帧使用相同目标负载，各自SLAM相机位姿按RGB时间戳对齐。Adaptive按已知负载映射预算，不含自动负载估计器或延迟反馈控制器。

## 最终实际占空比定义

本轮负载百分比以**人工负载占据的归一化SM时间面积**计量，不是等待GPU的CUDA Event时间，也不是整卡排他时间。每个SM内将人工负载Block的驻留区间求并集，跨SM求和后除以82个SM，得到该包的等效整卡ON时间Q。线程槽位面积和整个包的驻留包络另存。CUDA优先级不能抢占已运行的Renderer Block，因此不能保证每个短包完全独占所有SM。

每个有效渲染窗口累计许可A+=u_i×active_i，每个包计费C+=ceil(Q)。包量化引起的OFF余额跨帧偿还，条件结束仅补一次OFF，保证C≤A，累计SM占空比≤80%。不要将“存在任意SM的人工负载驻留包络/窗口时长”解读为本轮20%–80%目标；该值在部分SM并发时可以更大，必须单独公开。

使用普通CUDA网格492Block×512线程，最多3Block/SM，33024B共享内存/Block，两容量波次。二节点CUDA Graph先设置共同GPU截止时间，再执行8条FP32 FMA链。周期2ms，包ON目标为2ms×当前u，不含跨SM栅栏，GPU包驻留上限2ms。单一Graph复用，CPU只在前包排空后更新8B映射Host时长标量。

准备Stream最高优先级−5，人工负载−4，渲染0。准备、图像读取、质量统计期间负载暂停；渲染完成后排空当前ON包才允许下一次准备。完整请求计入准备、渲染、排空与门控；条件最后的OFF结清单列并摊销报告。优先级不是跨进程硬件抢占，不能保证其他项目的进程不干扰准备。

## 验收与测量

CPU准备完成不表示GPU验证通过。必须等待用户重新通知GPU空闲，之后才运行以下两个阶段，禁止自动监测空闲并启动。

先做40组相机/预算Graph与Native的选择ID、网络输出属性逐位对比，再对CaRtGS Full、我们Full、学生固定1k各跑完整2000帧负载验收。随后五种方法×三轮×2000帧正式采集，共30000请求。正式入口必须检查本轮实现哈希绑定的新GPU验收证明；旧smoke01–06均不能作为最终实现的验收。

每250帧统计实际SM占空比与该窗口时间加权目标，偏差≤5个百分点；计费采用向上取整Q，因此计费上限也约束真实SM占空比。访问覆盖时间加权≥99%，单包驻留≤2ms，人工负载与准备重叠数必须为0。逐包保留实际SM面积、线程槽位面积、包络及CUDA Event，不能仅凭目标值认定实际负载。

同帧头尾图像与无负载参考逐位复核。相机与有限形状Graph在计时前预热。每帧PSNR在计时外计算，不保存渲染图片。保存原始请求、八区间和全局mean/p50/p95/p99/std/CV、准备/渲染/完整耗时、K及候选不足。

图中三轮同帧取中位数，耗时51帧居中均值、PSNR81帧居中均值，预算与目标负载不平滑。统计使用全部原始请求，不剔除离群值；另附未平滑耗时图。1×3布局、英文图例：提交点数、完整响应耗时、PSNR。

## 负载实现诊断与废弃尝试

以下数据全部保留，不并入正式结果。诊断针对负载发生器，学生与渲染算法未改。

| 尝试 | 结果与原因 |
|---|---|
| formal01 | 原包络/Event计费；4046包中11包访问覆盖低于原单包95%要求。普通优先级无法抢占已运行Block。 |
| smoke02 | Cooperative Launch加各Block独立时长；仍出现分批启动，最长包3.226ms，弃用。 |
| smoke03 | 新增真实SM面积；稀疏32帧小窗出现5.84个百分点误差。改为完整250帧验收窗。 |
| smoke04/formal02 | 原包络/Event计费对CaRtGS与固定1k通过，对我们Full失败：SM面积93.21%，最高区间实际SM负载低12.85个百分点。表明包络/Event计费不能代表真实负载。 |
| smoke05 | 单容量网格加1.9ms硬超时握手，出现握手超时，有限退出而未死锁；弃用。 |
| smoke06 | 记录超时并继续验证，仍有SM面积93.36%、区间误差9.81个百分点。握手不能消除已有Renderer工作导致的偏差，弃用。 |
| 最终待GPU验证 | 恢复无栅栏普通短包，直接以实测SM时间面积反馈控制。保留80%真实SM占空比上限、2ms包上限和准备零重叠，避免将GPU调度等待计为人工负载。 |

最终协议在正式采集前确定，公开原计费模型失败证据；不得将两种占空比口径混合比较。SM面积反馈的GPU有效性尚未验证，不预先声明能够通过正式验收。
