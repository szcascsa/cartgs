# v11负载适应实验

本实验只使用冻结checkpoint和独立v11部署二进制，不修改训练入口、生产默认或共享conda。固定fr1_xyz RGB-D第396帧，比较CaRtGS Full、v11固定4000点和v11自适应预算。

用户已要求等待队列外训练任务自行结束。准入检查持续等待，不再使用十分钟超时；等待期间不创建CUDA上下文。只有队列保持暂停、连续三次GPU采样无外部活动且没有外部驻留计算进程，才进入短验收。任何实际测量阶段检测到外部GPU活动，本次测量报错并保留原始数据。

后续授权变更：用户要求即使存在其他服务也立即测试。此次使用 `--allow-recorded-background`，只放行启动前记录的既有计算PID，并记录其PID、启动时间、显存和逐秒SM活动；其他未知GPU活动仍报错。结果明确标注共享GPU条件，目标时间由当时环境下、未开启本轮人工负载的4000点P95标定，不再称为空载标定。既有服务负载波动是无法完全隔离的混杂因素，不据此声称独占GPU性能。

共享模式修正：首次正式测试中出现新的短时GPU进程，旧固定PID准入规则在第六组中止。该失败现场完整保留。用户授权允许其他服务，因此完整重测时对所有非本轮GPU活动进行记录而不中断；记录已知及新出现PID的启动时间和命令行，遥测覆盖不足、队列恢复或任何数值/严格K/完整性错误仍中止。未改变预算控制规则、人工负载日程或计时方式，未丢弃原始时序。

GPU负载程序按0、20、40、60、80、0百分比切换，每档5秒。每个调度周期1毫秒，按目标占空比提交不超过200微秒的多个CUDA计算脉冲，完成后再进入下一周期，避免积累异步队列。不同进程调度、频率与Kernel启动开销会使实测利用率偏离名义占空比，日志单独记录实际GPU活动和脉冲时间。

自适应预算只允许四档 `[4000, 3000, 2000, 1000]`。先在无外部负载下测固定4000点，取P95乘1.10作为目标时间 `tau_ms`。自适应方法每10帧计算一次窗口平均耗时。窗口均值超过 `tau_ms` 时降低一档，连续两个窗口低于 `0.85*tau_ms` 时提高一档。每次请求仍由v11依据名义Anchor候选和资格Mask计算实际K。

每个方法单独运行同一负载日程，重复三遍，方法顺序按轮次循环轮换。固定请求周期5毫秒，上一帧未完成则立即请求下一帧。每次先预热，再运行六个阶段。计时从请求开始到Rasterizer同步结束，包含选择、Compensator、打包和渲染。相机、模型加载和PSNR计算在计时外。跨阶段的帧单独标记，所有帧均保留。

主指标包括P50、P95、P99、标准差、CV、超出 `tau_ms` 的帧比例和负载恢复后的预算。附加记录实际K、候选N、资格E、阶段平均GPU利用率和方法的失败状态。四个K档位和原版Full的PSNR在计时前后单独评价并核对重复图像一致，固定相机下按实际使用K绑定质量。

GPU计时使用CPU墙钟前后同步CUDA。控制量只适用于RTX3090、当前v11和固定视角。负载程序与压测器都在研究目录中编译和运行，实验结束后自动检查生产项目、checkpoint和第三方二进制哈希未变化。
