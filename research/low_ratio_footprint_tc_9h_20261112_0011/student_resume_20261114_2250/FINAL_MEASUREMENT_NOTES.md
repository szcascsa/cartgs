# 最终验收口径

本轮预算为香港时间 2026-11-15 02:44:06—11:44:06；10:44:06 起预留报告和终验。所有历史收益单列，不能重新计为本轮收益。

1. 原入口对照为冻结 F2；本轮起点最快纯渲染对照为 ThinDispatch＋182。普通 182 也保留，便于分离轻量 Python 入口的已有收益。最终新渲染器通过同样的 ThinDispatch 提交；仅复用空 Tensor、内参标量与绑定方法，当前 Gaussian、相机、图像均重新提交和计算。
2. 原完整推理为 FP32 Selector＋FP32 Student＋F2；C 为已有 Tensor Core 与准备调度＋原生 C++ 相机＋F2；I_previous 为本轮起点已有 182 联合入口；D 为本次最终联合入口。Student 与 Selector 权重逐张量 hash 核对，不运行 Teacher 网络。
3. 纯渲染固定 Gaussian 身份、实际 K、位置、Scale、Opacity、SH、相机及背景。网络后端误差允许改变选点身份，重合率独立记录，不混入纯渲染测速。
4. 所有场景使用原协议 10 个视角：轨迹 43% 处连续 6 帧，以及 7%、31%、71%、97% 的跳转视角。双轮独立进程，逆转场景、条件和视角顺序，并均衡版本顺序。每条件每视角 12 个纯渲染墙钟样本；完整推理为 10 个墙钟样本。CUDA Event 与 Profile 独立记录。
5. 同步墙钟覆盖对应 Python/C++ 调用和最终 GPU 完成；给定 GPU 相机的独立准备阶段，不包含相机从 CPU 提交的成本。不能把它与不同计时边界的 Rasterizer 中位数相加当作完整路径。完整路径直接测量当前 CPU 相机到 RGB 完成。
6. Nsight Kernel 累计为 Profile 条件下的 GPU 节点时长；并非非 Profile 墙钟。NVTX 结尾主动 `cudaDeviceSynchronize` 属于测量同步，报告不能将其全称为部署必要同步。Profile 模块分类将 View 投影与 Student 主干/发布分开。
7. `alpha_interactions` 是诊断内 `weight>0` 的像素—Gaussian Alpha 累加次数；`alpha_participating` 是至少一次参与合成的唯一 Gaussian ID 数。它不是所有被访问、被阈值拒绝的候选测试次数。Tile 实例数来自阈值后的成员表；原始 `radii>0` 可见数保持独立。诊断图像与该版本正式输出逐位核对，诊断置于计时外。
8. 固定属性嵌套删点隔离实际 K 变化；真实 LoD 同时改变补偿后 footprint 和遮挡，不能把两类输入混为一种线性关系。局部 Ratio 的分母是当前名义 Anchor 候选池，Full 的 N 是全图；二者不等价。Full 自身加速还会使归一化耗时曲线升高，即使全部绝对延迟下降。
9. 质量门限使用每场景×条件的帧均值，再对条件等权平均。纯渲染两类输入分别验收；最终联合相对 FP32 Student＋F2 再验收。报告最差帧、SSIM、LPIPS，不能仅报告平均 PSNR。阈值3/255全局统一；4/255因固定属性保留条件均值超0.50dB被排除，不按场景选择阈值。
10. 性能表中的跨条件 p50/p95 总结是各条件中位数/95分位的算术平均；加速比为配对条件加速比的几何平均。全部逐帧、逐场景、逐Ratio、双轮原始样本及慢例保留。

最终实现没有每场景专用参数，不缓存旧视角预测、旧选点或旧渲染图片，不增加无效工作放慢 Full。
