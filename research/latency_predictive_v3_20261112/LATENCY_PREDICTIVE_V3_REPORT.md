# 0.2 ms延迟控制优化：预算上限、视角预测与实际开销

## 结论与建议

本轮完成了实际实现、编译、逐位检查和完整轨迹测试。视角预测控制能够更充分使用渲染预算，并改善较重视角的目标跟踪；它没有实现全轨迹每帧严格锁定0.2 ms，也没有提高整个推理流程的速度。

最终五方法配对实验中，0.19–0.21 ms原始命中率：原V2为11.18%，只解除8192上限为27.20%，视角预测控制为33.80%。在“同视角全部候选渲染耗时不低于0.19 ms”的子集中，命中率分别为28.57%、67.37%、82.96%。这个子集只用于事后解释，控制器不知道参照方法的耗时。

推荐根据目标选择：

- 优先低开销：保留V2控制律，将最大请求从固定8192改为当前冻结地图N；控制API Host中位数约0.057 ms，无新增几何摘要。仅加快PI限速未获得稳定额外收益。
- 优先接近目标：使用本轮BVH＋SIMD几何摘要及在线非负拟合。控制API Host中位数0.161 ms，较上述PI增加约0.104 ms；目标区间命中率更高，平均PSNR额外提高约0.043 dB。

本轮没有覆盖生产默认。训练、网络权重、Selector选点规则、Compensator数学和Mode40渲染器均保持原样，没有commit/push。

## 1. 完成标准与实验范围

完成标准为：独立实现可调用的推理控制器；同K下选点及图像不变；在同模型、同原生计时边界下比较目标跟踪、实际K、PSNR及Host开销；保留失败候选和原始结果；终检受保护服务器文件。

最终实验配置：

- Replica office2 RGB-D，完整2000帧轨迹，每方法3次重复，共30,000次单图请求。
- 原始1200×680，原始RGB评价，不缩放GT，不保存渲染图片。
- RTX3090，Intel i5-9600K。计时窗口67个约1 Hz负载样本，未检测到外部GPU活动或明显外部CPU活动。
- 同一43,197点冻结Master、蒸馏Compensator、Tensor Core D、新准备路径及Mode40。
- 目标0.2 ms；分别统计0.19–0.21 ms命中、严格超过0.2 ms、超过0.21 ms，三者不能混用。
- 初始请求3000，最小请求256；GPU按真实候选池计算实际K。候选不足时原有ratio=min(1,B/M)、K=min(B,eligible)语义保留。
- 五方法逐视角交错，轮换执行顺序；每轮创建新控制器，预测器不继承上一轮拟合结果。
- 每方法每帧一次prepare、一次render，无试渲染、未来帧预知或PSNR反馈。质量在计时结束后按记录的预算独立回放。
- 90 Hz调度针对包含五方法的视角组，不代表单方法显示FPS。

计时沿用V2原生Hook，覆盖输入更新Kernel与渲染CUDA Graph；不含准备、网络、Python、输出分配和Graph冷构建。所有方法使用同一Renderer和相同边界，没有通过更换计时范围制造收益。

## 2. 实际实现

### 2.1 解除固定8192上限

最大请求改为engine.total，当前场景为43,197。每次实际预算仍受当前GPU有效候选池限制；本场景有效候选数范围为2088–18,438。因此并不是每帧选择43,197点，也没有扩大名义Anchor视锥或引入视锥外候选。

解除上限单独作为V2对照，避免把增加可用预算误归因为预测器。

### 2.2 当前视角几何摘要

初始化时从冻结engine一次性读取Anchor中心、名义半尺寸、有效成员数，以及成员物理Scale平方的平均值。此后不逐帧下载GPU矩阵或候选Mask。

在CPU建立有界BVH，包围盒覆盖Anchor名义立方体。每帧使用调用方已有的camera-to-world和CPU投影矩阵：

1. 完全在视锥外的节点直接跳过。
2. 完全在视锥内的节点直接累计成员数。
3. 交界节点向下遍历，叶子使用AVX/FMA一次检查8个Anchor。
4. 使用节点或可见叶子集合的中心、平均Scale及深度估计投影覆盖代理。

GPU仍执行原有精确候选筛选、Selector与Compensation。CPU摘要不会替代GPU选点，也不会修改任何Gaussian参数。

覆盖代理不是像素级真实交互次数。近似投影量为：

```text
s ≈ (fx² + fy²) × mean(scale²) / max(depth, 0.01)²
h = 对可见集合按有效成员数加权的 s / (s + 64)
```

节点聚合忽略了成员方向、遮挡和补偿后footprint，只用于控制器预测。最终实验6000次预测请求中，CPU候选数与GPU有效候选数100%相等；这是本场景实测，不能外推为任意浮点边界下的形式化等价。

这不是同帧Mask缓存：每个新位姿都重新遍历BVH。缓存仅保存冻结地图的空间结构与几何摘要。

### 2.3 四变量在线耗时模型

特征为：

```text
x = [1, sqrt(K/4096), h × sqrt(K/4096), K/N_visible]
t_pred = theta · x + bias
```

theta各分量非负，使模型内部预测随K单调。拟合只使用已完成帧的实际K、当时的几何摘要、GPU真实候选数和原生渲染耗时。

实现采用四变量非负加权最小二乘，衰减系数0.97、轻量对角正则0.0001，枚举16个活跃集合。固定维度的Gram矩阵及交叉项有界，不保存不断增长的样本历史。bias按0.2新样本权重更新，并限制在±目标的25%。

初始化使用按目标缩放的通用先验，不读取此前完整轨迹的耗时曲线。目标切换重建拟合；相机切换清除近期反馈状态。相近K和几何摘要下若耗时突变超过目标的30%，重置模型适应负载变化。这只是软件恢复机制，尚未完成外部重负载实验验证。

在当前候选上限内二分查找预测不超过目标的最大K。普通更新每次最多增加35%或减少40%；明显超时且几何摘要接近时，另有按实际耗时比平方计算的快速退避，可能突破普通下降限速。GPU始终执行最终预算裁剪。

### 2.4 异步反馈与生命周期

复用V2有界CUDA Event环及原生Renderer计时协议。每个反馈绑定frame、epoch、K、候选上限、提交时间及对应视角摘要；积压时只用最新完成样本决策，不等待GPU。

冻结地图、网络、拓扑、Anchor归属、设备或分辨率变化时必须重建实例。Controller不支持在旧摘要上继续训练或Clone/Split/Prune。没有修改训练流程来维护这份推理专用结构。

## 3. 最终完整轨迹结果

所有数字来自同一轮五方法交错实验，均为三次重复的原始单次请求，不做异常剔除或平滑。

|方法|平均ms|p95 ms|p99 ms|0.19–0.21命中|超过0.2|超过0.21|平均K|PSNR dB|
|---|---:|---:|---:|---:|---:|---:|---:|---:|
|V2，8192上限|0.170429|0.196387|0.204513|11.18%|2.80%|0.17%|7120.8|30.1374|
|V2，仅解除固定上限|0.176024|0.207234|0.213025|27.20%|14.58%|2.38%|8119.8|30.2008|
|快速PI，解除上限并匹配35%/40%限速|0.176184|0.208000|0.212896|26.53%|14.67%|2.92%|8167.8|30.2179|
|BVH＋SIMD预测控制|0.177435|0.204032|0.211969|33.80%|12.90%|1.25%|8378.3|30.2434|
|补偿后的全部当前候选，参照|0.184154|0.233603|0.342820|21.28%|23.83%|16.47%|9464.6|30.2848|

“全部候选”使用原网络在ratio=1条件下的当前视锥候选，不等于未补偿的全地图Full Rendering。

归因：

- 解除上限贡献了较大一部分改进：11.18%→27.20%。
- 同样解除上限后，预测器进一步提高命中率至33.80%，超过0.21 ms的比例从2.38%降至1.25%。
- 匹配35%/40%限速的快速PI仍只有26.53%，说明预测器的收益不能全部解释为加快限速。
- 相对原V2，预测器平均PSNR提高约0.106 dB；相对解除上限的PI，提高约0.043 dB。这里预算和选点数量本来就在变化，不能称为同K画质改进。
- 预测器仍有75/6000次超过0.21 ms，最大0.340864 ms；没有硬实时保证。
- 预测器严格≤0.2 ms的比例为87.10%，低于更保守的8192上限V2的97.20%。它改善的是接近目标和预算利用，不是对严格时限违规率的全面改善。

## 4. 为什么仍不是每帧0.2 ms

全部当前候选这一实测端点，有62.25%的请求仍低于0.19 ms。预测控制自身有61.20%的请求已经使用全部当前候选且仍低于0.19 ms。当前候选域已经用尽，继续改控制器无法在这些帧增加有价值的渲染工作。

该端点不是对所有K的单调性证明：网络ratio会改变补偿，少点也可能产生大footprint。它只说明当前全候选端点的实测范围，因此不能把62.25%简单当作理论不可达比例。

按参照端点≥0.19 ms划分，2265/6000次请求属于较重视角；该子集的目标区间命中率为：

|方法|较重视角命中率|
|---|---:|
|V2，8192上限|28.57%|
|V2，仅解除上限|67.37%|
|快速PI，相同限速|66.05%|
|视角预测|82.96%|

其余误差来自当前代理对补偿后footprint、Tile分布和遮挡的描述不完整，以及异步反馈、计时抖动和实际耗时不严格随K单调。预测器平均绝对预测误差为0.005893 ms，仍足以使部分请求越出±0.01 ms区间。

没有通过插入等待、重复点、扩大候选域或故意增加无意义计算制造0.2 ms命中。

控制API统计request/start_native/finish，包含当前测试中的pybind、Stream检查、Event调用和预测。产品Wrapper不需要每帧额外读取遥测。

预测器的几何摘要本身中位数81.75 μs、p95为130.49 μs。初始化摘要读取和构造输入数组约2.90 ms；BVH建树位于configure_view，未包含在此2.90 ms中，全部发生在计时前。

常驻CPU空间：原始摘要数组401,352字节；Controller内部Anchor、BVH和SoA实际容量1,522,112字节。没有新增逐帧GPU归约或读回，也没有新增GPU特征缓存；Event环与V2同规模。允许更大请求使原有准备与渲染Workspace可能扩大，本轮所有方法共享相同预热后的Workspace，不能据此声明整个应用显存没有增加。

CPU空间结构逐步优化后的控制API中位数：

|实现阶段|Host中位数|
|---|---:|
|逐Anchor扫描＋稳定非负拟合|954.90 μs|
|标量BVH|309.45 μs|
|BVH＋SIMD|164.61 μs|
|最终五方法配对中的BVH＋SIMD|161.47 μs|

各阶段分时运行，不能将差值当作严格配对的CPU算子加速比；它们支持降低开销的方向，最终开销以五方法配对表为准。

重要限制：Host阶段prepare＋控制API＋render调用的均值，解除上限PI约0.5655 ms、预测器约0.6634 ms，不含独立遥测。它们不是GPU完成到显示的端到端帧延迟，但已说明预测器增加了Host工作。本轮没有证明完整推理更快，不能将目标跟踪改善包装为整体速度提升。

当前SIMD构建针对服务器x86 AVX/FMA。ARM设备需要对应NEON实现和重新实测；没有声称已在Quest3原生设备运行。

## 6. 失败候选与修正

1. 投影RLS失败：将无约束RLS系数直接裁为非负，破坏了相关特征下的协方差更新语义。完整轨迹出现长期低预算：74.02%请求降到256点，PSNR约20.6350 dB。该实现不保留为可用模式；源码、二进制、日志和原始数据归档在failed_rls_*。
2. 非负拟合修复数值状态，但逐Anchor扫描仍约0.955 ms控制开销，不适合作为最终低开销方案。
3. 标量BVH将开销降至约0.309 ms，仍偏高。最终改用SoA、每次8 Anchor的SIMD筛选、节点聚合及有界覆盖代理，控制开销降至约0.161 ms。
4. 仅加快PI限速：最终配对没有稳定优于原限速，因此不推荐将35%/40%简单作为默认改动。
5. 测试构建入口曾因手写V2二进制哈希拼写错误而在smoke阶段退出；改为读取已核验的V2身份清单，未绕过校验。原失败现场保留。

## 9. 下一步最有价值的验证

1. 若优先整个推理流程的效率，应采用解除上限的PI作为低开销基线；预测器相对它的0.043 dB收益和约6.6个百分点命中提升，需要与额外0.104 ms Host成本一起判断。
2. 若优先跟踪精度，应研究在原准备流程中复用当帧候选及几何统计，把预测参数上传和预算求解放到现有Device控制节点，避免CPU重复几何查询；必须保持一次prepare、原有限值检查及GPU预算语义。
3. 若要求严格≤0.2 ms，应另设带安全余量的限时目标，并报告违规率与画质代价。当前算法以接近0.2 ms为目标，不能将87.10%严格达标率解释为硬时限保证。
4. 目前只验证office2空闲GPU。跨场景及外部负载突变必须另外测试；本轮不推断这些条件下仍有同等收益。
