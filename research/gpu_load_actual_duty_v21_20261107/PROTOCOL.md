# 全SM人工负载与实测占空比

本轮实现用户要求的强人工负载，保留v21准备网络最高优先级与人工负载仅在渲染阶段运行的约束。占空比输入范围为0至80%，负值、NaN、无穷和超过80%直接报错。

## 占空比定义

实测驻留占空比定义为每个完整渲染窗口内各负载Kernel的GPU驻留包络时间之和，除以完整窗口墙钟时间。窗口从resume请求起计，到pause确认负载排空且补足OFF时间结束。每个Kernel读取GPU globaltimer，记录每个Block的入口、出口和SM编号。

CUDA Event间隔可能包含排队和调度空隙，因此将它和GPU驻留包络取较大值，作为保守计费ON时间。每一包结束后，要求累计窗口长度至少达到累计计费ON时间除以目标占空比，才允许下一包或确认pause。这样将实际测得的驻留占空比及保守计费占空比限制在用户目标以内。

80%约束作用于完整窗口及每次结清OFF时间后的累计周期。ON子段允许覆盖全部SM。任意截取一个ON子段时，其瞬时占用可能接近100%。短窗口或强外部争用可能使实际占空比达不到目标，必须报告实测偏差。

globaltimer入口至出口区间可能包含驱动抢占期间的时间，不能据此计算精确的独占执行份额。单独记录平均SM驻留时长和CUDA Event时间供复核。若需要精确区分驱动调度造成的暂停，需要额外GPU调度时间线采集。

## ON段资源

使用cooperative launch，每Block 512线程，每线程8条独立FP32 FMA链。根据设备每SM最大线程数设置Block数，预留允许这些Block同时驻留的最大共享内存，并通过CUDA occupancy API核验。RTX 3090每SM采用3个Block，共1536线程，覆盖全部可驻留线程槽。每包核对SM编号去重数量及每SM的Block数。以20毫秒名义周期计算ON段，20%至80%对应4至16毫秒计算时间，设备globaltimer控制计算循环，避免依赖GPU频率估计脉冲长度。实际OFF时间按测得的ON时间闭环补足，GPU Kernel因驱动调度而延长时也计入保守时间。pause和析构都必须等待当前包完成并结清OFF时间。

初次100微秒脉冲验收的80%档仅达到约29%驻留占空比，逐包CPU提交及跨进程排队占据了其余时间，该阶段保存在validation01。第二次5毫秒名义周期的80%档约65%，保存在validation02。按上述机制继续修正ON段长度后重新验收，不将旧阶段的上限通过误认为占空比目标匹配通过。

准备网络保留最高Stream优先级，人工负载使用下一档优先级，渲染仍为默认Stream。cooperative launch和资源预留增强同上下文的竞争压力，普通CUDA无法保证其他进程完全停止。其他进程仍可能由驱动分时运行。

## 验收

CPU测试覆盖80%硬上限、异常输入、可变ON耗时及OFF时间结清。GPU验证包含三轮0、20、40、60、80、0%窗口，每窗150毫秒，以及v21的1000与4000点请求。每次请求检查像素一致、全SM覆盖、负载包边界和实测占空比上限。目标匹配误差以正负5个百分点为观察标准，低于目标的情况单独记录，不修改目标来适配结果。

本轮范围为新负载程序的实现和短验收，完整三方法负载曲线另行运行。服务器与本地均使用独立目录，checkpoint只读复用。
